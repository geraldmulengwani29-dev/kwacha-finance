## 2026-07-14 - Fail-Open Authorization Bypass
**Vulnerability:** A fail-open authorization bypass existed in the global authorization handler within `src/App.js` inside the `onAuthStateChanged` hook. If a user didn't have an explicit Firestore client profile document (or if the document lookup threw an error), the system defaulted their role to 'admin' and granted them administrator privileges.
**Learning:** The database query was structured such that the `exists()` conditional was followed by an `else` block that assigned 'admin' permissions, rather than a restrictive default. Furthermore, lack of error handling around database queries meant that transient network or Firestore query failures could leave user state partially updated or hanging.
**Prevention:** Always follow the principle of least privilege. The default state in any authorization fallback (missing document or thrown database error) must always resolve to the most restrictive role available ('client'), failing securely under all circumstances.
